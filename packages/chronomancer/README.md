# Chronomancer (local prototype)

Quiet capture and deliberate rewind in Pi. A **standalone dated Markdown journal** is the source of truth; Neovim is optional. On this machine, `/Users/jordan/.pi/agent/settings.json` loads this package in normal Pi. Loading it registers commands but does **not** activate journal capture or the mirror. It does not switch Pi conversation sessions, alter `/tree` or `/fork`, or submit thoughts to a model.

## The movement

Events move forward; their meaning can continue to develop. Chronomancer never changes the original thought or pretends a later reply was written in its past. Red is the thought as first sent. Orange travels toward older roots; yellow returns toward newer thoughts through **only the orange branches you actually saved**. Green goes older through saved yellow branches, and blue comes newer through saved green branches. An entry keeps its original color and actual creation time; the *next editor* changes color. Each pass is an invitation, not a completion requirement. A skipped thought stays dormant and can be visited on another pass. The journal records links between moments, not a score, deadline, or agent's theory of your life.

The purple question is never an automatic reward. After a blue thought, you may explicitly invite one. Silence, red capture, and leaving the journal are always valid choices. The movement should make attention responsive without requiring every thought to be answered.

## Start and reconnect

Launch `pi` normally from the directory you want to journal (on another machine, install this package first). Type **`/chronomancer`**. There is no setup picker or path to enter: it recognizes the journal in the current directory (or its `chronomancer/` subdirectory), or creates `chronomancer/` if none exists. The bottom red composer targets **today** on entry; the dated file is created only when you send your first thought. A saved personal color pass may resume on an older day independently of that red capture target. Each working directory can have its own journal. An existing directory without a valid journal marker is *not* silently converted or overwritten.

`/chronomancer create` is an idempotent alias for the same local discovery. To deliberately open a journal outside this directory, use `/chronomancer connect /absolute/path/to/chronomancer`. That reconnects Markdown, **not** a different Pi conversation. `/chronomancer off` restores ordinary Pi input; `/chronomancer on` re-enters the last connected journal (or opens this directory's journal) on today. Existing Pi session titles remain unchanged. When Home is loaded, Chronomancer mode suppresses the Composer's run-state / `your turn` label without modifying `/footer` preferences.

## Two-pane mirror: Pi agent + human journal

Start Pi and Neovim **in the same working directory**. Keep the Pi pane in ordinary agent-chat mode and run `/chronomancer mirror`. Open `:Chronomancer` in Neovim. When you save in Neovim's red or colored composer, the saved thought appears in its journal view and in Pi's read-only **JOURNAL MIRROR** above the normal agent editor.

**To read everything, run `/chronomancer mirror read`.** In fullscreen Pi you can also click the mirror. The reader includes every available saved day, complete thought bodies, original stage colors, and explicit `reply to #N` links. Days are ascending and entries retain the Markdown journal's parent/child order. There is no 280-character or eight-source-line body limit in the reader. It starts at the beginning; new saves and external edits refresh it without deliberately jumping away from the thought being read. End opts into following the latest content.

| Key | Reader action |
| --- | --- |
| Up/Down or J/K | Scroll a line |
| PageUp/PageDown or Space | Scroll a page |
| N/P | Next/previous thought |
| `[` / `]` | Previous/next saved day |
| B | Jump to the current thought's parent |
| Home / End | Start / latest content and follow new saves |
| `?` | Scrollable keyboard help |
| Escape or Q | Close help first, then close the reader |

The fullscreen mouse wheel also scrolls; regular Pi has the same keyboard paths. The reader is a temporary overlay: closing it returns to the same native agent editor and unsent draft. The small above-editor mirror remains a **labeled latest-entry excerpt and launcher**, bounded by terminal height so it does not consume the composer. It shows a thought count and the full-journal command; it is not the place where all journal text is displayed at once. Neither surface is a second Pi transcript.

Mirroring does **not** call a model, insert a Pi session entry, intercept ordinary Pi chat, send agent replies to the journal, or transmit unsent drafts. `/chronomancer mirror off` stops it without changing capture mode. If the panes started from different directories, use `/chronomancer mirror connect /absolute/path/to/chronomancer` to point Pi at Neovim's journal. `/chronomancer status` shows the mirror's journal path; in Neovim, `:Chronomancer status` shows its path. Directory watching refreshes promptly after an atomic save, with a periodic reconciliation if a filesystem event is missed. Reconnecting loads all available saved entries for the reader and chooses the newest saved thought for the launcher, without fabricating earlier live events. `mirror read` can discover an existing local or capture-connected journal without creating a new one; the explicit `mirror` command retains its local creation behavior. Reader navigation is memory-only and does not modify color-pass checkpoints. Turning the mirror off, reconnecting, session replacement, or shutdown closes its reader; tree navigation closes the reader without rewriting the external journal. Unreadable or disappeared day files are reported, and the observer retains its last valid snapshot instead of presenting corruption as an empty day. A reader warning remains until reconnect; reconnecting cannot recover missing files. Explicit journal capture from the agent-chat pane and an editable full branch projection there are future work.

## Capture and revisit

- In mode, Enter in Pi's native bottom composer saves a red H1 thought to `YYYY-MM-DD.md` **without a model call**. It appears in Pi's transcript with the same native user-message body, speaker, Sent label, and frame as a normal sent message; it is a durable display entry, not an agent prompt. The selected journal date stays visible above the editor. The Markdown journal can be opened or reviewed by any editor or agent.
- `/chronomancer day YYYY-MM-DD` selects an old day for new thoughts and child additions. `/chronomancer today` returns to today. The selected old day stays selected until explicitly changed. When following today, the date rolls over at the next capture after local midnight.
- In **fullscreen Pi**, **Shift+Up from the bottom red editor** starts orange rewind without a command. `/rewind` is an alternative. The orange editor appears *beneath the original red frame* if that root is mounted in this Pi session; it does not append a colored revisit. **Shift+Up/Down** move among thoughts. Enter saves a linked child and advances. At the oldest root orange **pauses**; the hint says `YELLOW ready (N)` or `no YELLOW yet`. **Shift+Right** at an edge enters the next saved-branch color if one exists; **Shift+Left** from anywhere in a colored pass returns to the prior pass's edge, or focuses red from orange. Yellow, green, and blue follow the same deliberate direction gestures; neither crossing a boundary nor moving back marks a thought done or undoes a save. Blue rests at a navigable edge, and `/rewind` can begin another orange visit after it. Purple still requires `/chronomancer ask`.
- **Alt+R** toggles between the active colored editor and the still-visible native red composer. After a pass has begun, **Shift+Up from red** returns to its colored editor. Pi reserves Shift+Tab for thinking level, so Chronomancer does not override it. The bottom composer frame takes on user-message red while Chronomancer is active and returns to its Home color on exit; an explicit `/workspace` frame-color choice still wins. The red draft and each branch's colored draft remain separate while Pi runs. A personal pass checkpoint (`.chronomancer-progress-owner.json`) travels with the journal and can be resumed in Neovim; unsent drafts remain local to the running client. Plain Up/Down remain editor movement; Enter at the bottom always creates a new red thought. Navigation, skips, and saves do not prompt a model. The frame under each saved parent is indented to show ancestry while its right edge aligns with the red frame.
- In **regular Pi**, terminal-owned scrollback cannot host this editable historical position; `/rewind` retains the earlier orange revisit near the composer and `/chronomancer add` uses a temporary child editor. In fullscreen, if the selected journal root was saved in a different Pi session and is not mounted in the current transcript, Chronomancer warns rather than pretending an appended copy is the original. `/chronomancer add` still offers the temporary editor for that root. A dedicated journal projection across sessions is further work.
- `/chronomancer add` focuses the inline editor beneath a mounted selected parent in fullscreen, otherwise opens a temporary editor for a child. `/chronomancer deeper` selects a saved child. These remain escape routes when the selected root is not in the current transcript.
- At blue, `/chronomancer ask` **explicitly** invokes the selected Pi model for one purple question. The question is in Pi's session, **not** a journal submission. No model is called automatically when you reach blue.

Each entry has its own ID, explicit parent, selected journal day, and an ISO `created-at` timestamp for when it was *actually written*. An addition to an older day is filed there but retains today's real creation date. A new red entry matches Home's default sent-user frame; a regular-mode red-root revisit uses the same frame in orange with a ↶ marker, while fullscreen keeps the original red frame and puts an orange editor beneath it. Saved child frames retain the user-frame shape and change border/identity/Sent color by stage. The displayed `Sent YYYY-MM-DD …` label at bottom-right uses the real creation date for an older selected day. When Home is loaded and an actual Pi message has a sourced Sent time, its frame shows the **real YYYY-MM-DD** during past-day mode; normal-mode formatting returns on exit. Older/unsourced messages do not acquire invented timestamps.

## Boundaries

This is a local prototype. The orange-to-yellow-to-green-to-blue traversal is available for branches under red roots **mounted in the current fullscreen Pi transcript**. It has no score, sound, or idle animation; the intended responsiveness is in focus, placement, and the consequence of saving or skipping. A root from another Pi session or an older day that is not mounted here cannot yet have a truly inline editor; an editable inline journal projection remains future work. The mirror reader can already display complete saved history across sessions without mounting editable roots in the Pi transcript. Regular Pi retains the revisit and temporary editor fallback; `/chronomancer bounce` works there without an inline Shift+Right key. Unsent colored drafts are memory-only across Pi reload/exit, although switching focus and navigating mounted branches preserves them while Pi runs. The native bottom draft and pi-vim editor instance are not replaced. Connecting to a journal *outside* the current working directory requires its absolute path; the mirror reader browses all saved days within that connected journal, not a directory of unrelated journals like a session picker. One Pi conversation can visit many dated files, and a later agent review must read those files deliberately; the whole journal is not automatically inserted into model context. Pi and Neovim share the marker-v1 UUID/parent Markdown format. The former `time/YYYY.MM.DD.md` notes remain an untouched archive; normal Neovim startup no longer exposes a legacy importer. Entries with `created-at=unknown` still receive no invented Sent label. Pi still cannot mount an older root inline if that root is absent from its current transcript, although its selected pass position is restored. Purple-question model usage is not yet counted as a Pi session usage entry.

No new setup screen is needed: the child editor is Pi's native editor, the selected-day hint is a small native widget, and transcript entries reuse the installed `pi-embeddable-frame` package shared with Home. Keep that package resolvable when installing Chronomancer elsewhere. Writes use IDs, heading-depth validation, an exclusive lock for cooperating Chronomancer processes, a fresh disk read and atomic replacement. Pass checkpoints use a compare-before-replace guard so a stale client warns instead of deliberately overwriting newer progress; local file guards are not a multi-device offline sync protocol. Unknown or malformed day files, structural headings in drafts, symlink day files and missing parents are rejected. A simultaneous non-Chronomancer editor write in the narrow interval between the final disk check and rename cannot be excluded; coordinate edits when both apps write the same day. If a Pi input write fails, the submitted text is restored to the editor if it is still empty.

Mirror reader regressions cover complete long bodies across days, parent/day/thought navigation, live saves and stable reading anchors, narrow/short dimensions, light/dark themes, terminal-control sanitization, scrollable help, mouse dispatch, overlay lifecycle, unchanged journal bytes and untouched agent input. Package tests are separate from root `npm test`; run both when changing the mirror. Human TUI checks (Home/pi-vim focus, real mouse dispatch/selection, resize, theme, date rollover and a real model call) remain necessary.
