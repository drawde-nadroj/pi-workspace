# Egregore UI

Egregore is a **Composer-only** appearance extension verified against Pi 1.3.0. It frames Pi's native editor and transcript, hosts the optional Tasks dock, and owns the `/egregore` appearance editor. Its appearance layer does not replace the text engine or own Tasks plans or Ask answers. The separately enabled [activity recap feature](#optional-activity-recaps) can make additional model calls; it defaults off. The retired Home looks and `/home lab` gallery are not part of this checkout; their history remains in Git.

**Installation status:** After explicit approval, the live Pi settings load this checkout's private suite, which explicitly loads Egregore, Tasks, Ask and Quests and bundles `pi-embeddable-frame` and `pi-agent-contracts`. The older personal Home directory was removed; the older Tasks directory remains excluded from auto-discovery. Separate Frame/Ask package declarations were replaced. An already-running Pi session needs a fresh start to use the suite. See [acceptance](../../docs/ACCEPTANCE.md) and the [switch/rollback record](../../docs/MIGRATION.md).

For a first exercise, [try a reversible preview](../../docs/TRY-PREVIEW.md). For a specific task, use [workspace controls](FOOTER.md), [commands](#commands-and-preferences), or [recap consent and processing](#optional-activity-recaps). Installation belongs to the [suite setup guide](../../docs/INSTALL.md); the machine-specific migration record is not a portable recipe.

## Composer

Composer is the fresh-install default. `/composer on` re-enables it; `/composer off` restores the preceding native editor/header and theme while leaving the independent configurable footer and Tasks fallback available. An old `pi-home.json` with a retired `look`, `scene`, `gaze` or `motion: "ambient"` is **read without rewriting it**: the visual look becomes Composer, obsolete fields are ignored, and the next explicit `/composer` preference save writes only supported fields to `pi-composer.json`, leaving the legacy file unchanged. No plan, session or draft data is migrated or deleted.

- The real editor instance keeps its draft, paste, cursor, undo, completion and selection. Optional pi-vim 0.14.2 requires the documented [Windows undo alias](../../docs/INSTALL.md#optional-pi-vim-0142-on-windows); without it, Vim undo fails even without Egregore. With pi-vim installed, Egregore decorates its existing editor rather than replacing it. Native scroll hints take priority; tiny or graphical surfaces fall back safely.
- The top input rail shows real run state at left, the session title in a **static softly tinted badge** in the center and the **last recorded user-send time** at right. The badge retains configured title color/position and uses a contrast-aware background. Ordinary metadata is no longer forced bold; explicit element weight settings and native Vim emphasis remain authoritative. Before a send, an optional display-only hint may occupy that slot. It never guesses a timestamp from another branch or calls a model for it. The bottom rail shows directory, native Vim mode if present, and model plus selected thinking level. Context usage can be enabled in `/egregore` but is hidden by default. In a viewport (fullscreen) TUI the bottom rail also carries a microphone: it shows `REC <n>s` while capturing and inserts the local transcript at the editor cursor. It is an operational control, not an appearance element, so `/egregore` neither styles nor saves it; the regular TUI never receives pointer clicks and omits it there. See [dictation](#dictation).
- A five-cell **living ember** beside the status is the primary activity cue. Its grid choreography follows real work: thinking traces a figure-eight comet, writing runs a four-lane conveyor, tools use twin counter-orbiting comets, compacting collapses four corner sparks into the centre, and generic working crawls a serpentine trail. Tool starts briefly lengthen tails and brighten heads; the label and input perimeter stay still. Ordinary typing does not dim or pause it. Focused dialogs/settings and either motion-off control stop it. Waiting, finished, failed and stopped states use static markers; narrow rails drop the marker before the status text. Current tool names follow the state/time and yield first when space is limited. There is no idle animation or predicted progress; task and question semantics remain separate.
- Native user and assistant messages receive guarded transparent frames with sourced **Sent** creation times. Unsupported content, graphics and narrow views retain Pi's native renderer. Grouped ordinary text calls keep each native child and its expansion/mouse handling; the separate web adapter applies only to its allowlisted tools. Tool errors and cancellations keep semantic markers. See [ACTIVITY-BLOCKS.md](ACTIVITY-BLOCKS.md).
- In fullscreen mode, the native top-right `Copied!` notice has a compact neutral-gray pi-frame border and ordinary text. Pi retains clipboard handling, placement and expiry; errors and other notices remain native. Small screens and unsupported host renderers use native feedback. Composer off restores the native notice.
- Fullscreen copying omits the outer rails, side borders and Egregore-added padding of supported chat and tool frames. Literal pipes, border-shaped content, code indentation and internal blank lines remain intact. This uses recorded component/render geometry, not a character filter. Regular terminal selection, fixed docks, self-rendering tools and unsupported/stale layouts remain native; their borders can still be copied. Composer off restores native extraction.
- The optional Composer theme is a reversible runtime lease; `/composer theme off` restores preceding interface colors without changing Pi's saved theme setting. Egregore off also releases the lease. Terminal/font legibility still needs visual review.

The optional Tasks extension publishes a data-only plan snapshot to Egregore. A compact sourced checklist can appear above the input, with a bold, softly highlighted active row and explicit Working/Paused wording. Fresh Tasks presentation defaults to a brief 1200 ms highlight on focus/completion changes rather than continuous border motion; saved presentation choices remain authoritative. `/tasks` opens the work list and plan library. Egregore never starts or completes a task, and Tasks retains its standalone fallback. See [DOCK.md](DOCK.md) and the [Tasks README](../pi-tasks/README.md).

## Session activity

Meaningful Quests and Tasks changes appear above the Composer. `/activity` opens the recent session history (up to 200 updates) and lets you inspect the referenced quest or task plan. Events are recorded on the session branch; opening another branch restores its own history. The cross-session quest journal remains separate.

Use `/egregore` → **General** → **Session updates** to choose compact (latest update), expanded (three updates), or off. **Session update colors** chooses semantic jade/gold/Tasks accent or neutral theme text. These controls use the existing preview, Save, Discard and Undo transaction in `pi-egregore.json`. Off hides the strip without deleting history. Updates have text labels as well as colors. No animation, background model request, editor replacement or automatic execution is added. Source inspection is read-only; continue work in `/quests` or `/tasks`.

## Notification sounds

On macOS, Egregore plays React Bits **Pluck** once when an interactive run settles successfully, after retries and queued work finish. A quieter **Hint** plays when a blocking `ask_questions` or `ask_user_question` form opens, once per tool call rather than once per nested dialog. Errors, cancellations, ordinary tools, settings dialogs and passive posted-question browsing are silent. Noninteractive modes never play automatic cues.

`/sounds off` mutes automatic cues and stops current playback; `/sounds on` enables them. `/sounds` reports the current state. `/sounds test` previews Pluck and `/sounds question` previews Hint, even while muted. These operational controls are session-only, independent of Composer appearance and `/egregore` Save; restarting or reloading restores the platform default. No saved settings are changed.

Playback uses macOS `/usr/bin/afplay` and bundled WAV exports, without React, browser access or runtime downloads. Other platforms default off and report unsupported playback if explicitly previewed. Playback failure disables automatic cues with a warning; shutdown/reload stops owned players. Volume follows system output, with Hint played at 60% of its original amplitude.

The sounds are original exports from [React Bits Sound Lab](https://reactbits.dev/tools/sound-lab), pinned and attributed in `assets/sounds/PROVENANCE.json`. Their bundled `LICENSE.txt` is **MIT + Commons Clause**, distinct from this suite's MIT code license; application embedding is permitted, but standalone sound-pack redistribution is not.

## Dictation

`/dictate`, or the bottom-rail mic in a fullscreen TUI, records from the default system microphone, shows `REC <n>s`, and inserts the local transcript at the editor cursor on the second press. Capture is one `ffmpeg` child process at 16 kHz mono; transcription is one `whisper-cli` run. Nothing is uploaded and no npm dependency is added. A recording is capped at five minutes, a prompt closing cancels it, and Composer off disposes it.

The first use without a model asks once before downloading `ggml-base.en.bin` (142 MB) into the platform cache. The download streams to a `.part` file, checks the SHA-256 Hugging Face announces on its redirect, and never leaves a partial model behind; declining writes nothing and the next press offers it again. Missing tools show `mic !` plus a platform-specific setup hint instead of failing silently; a configured path that exists but cannot execute is reported as a warning (`ffmpeg could not start (EACCES): …`) rather than terminating Pi, and every child's stdio streams are error-guarded because ffmpeg closes a non-terminal stdin.

| Variable | Effect |
| --- | --- |
| `PI_DICTATION_MODEL` | Model path; replaces the cache/Homebrew/`~/.local` search |
| `PI_DICTATION_LANGUAGE` | whisper.cpp language, default `en` |
| `PI_DICTATION_MODEL_URL` | Alternate model URL, still consent-gated |
| `PI_DICTATION_FFMPEG`, `PI_DICTATION_WHISPER` | Explicit tool paths instead of `PATH` lookup |
| `PI_DICTATION_INPUT` | Capture device: `:N` (avfoundation), `audio=<name>` (dshow), `pulse:<device>`/`alsa:<device>` |

Dictation writes no preference file: `pi-composer.json` and `pi-egregore.json` are untouched, so `/egregore` neither styles nor saves the control. The mic is omitted where clicks cannot arrive — the regular TUI never enables mouse reporting — and below 40 columns, where `REC` plus seconds could not survive a centered mode label; `/dictate` is the keyboard path in both cases. A click on the rail never takes keyboard focus, and text insertion prefers the editor's own cursor insertion over rewriting the draft. Windows and Linux capture argv and their failure hints are unit-tested, but their real device paths are not exercised by this checkout's automated runs.

## Customize with `/egregore`

`/egregore` opens one transactional workspace with **Input**, **Tasks**, **Ask**, **Transcript**, **More settings** and **General** sections. Aligned Part / Setting / Value headings, shorter names, explicit empty values and view-only advanced groups reduce clutter without dropping controls. Select a semantic element using keyboard navigation or a clickable preview region in fullscreen mode; all four rooms identify the affected target persistently and name its location. Supported pointer-move events provide static, display-only hover inspection without editing or stealing keyboard focus. State/color/position and other safe choice menus offer reversible hover and keyboard audition; only Enter/click accepts a candidate, and Save never commits an unaccepted hover. Menu coordinates remain stable across preview-height changes. Hidden or clipped targets receive an explanation. Edit safe text, placement, color and state treatment where exposed. Composer previews the real full-width native editor without changing its unsent draft. The other rooms use explicitly display-only synthetic samples. **Ctrl+S** saves, **Ctrl+Z** undoes and **Discard** restores the saved state. Unknown future Ask or Transcript versions block Save instead of being overwritten.

Global presentation preferences are saved atomically to versioned `pi-egregore.json`; existing `pi-workspace.json`, then `pi-footer.json`, are read when the primary is absent and never rewritten by migration. The General room uses synthetic message examples to demonstrate your sent-message display name and the single Compact/Spaced **Spacing** setting. Supported user/assistant message frames and General/Transcript message examples have no extra edge rows in Compact, or one blank row above and below content in Spaced; paragraph/code gaps remain unchanged. Composer operation uses `pi-composer.json`, with a read-only `pi-home.json` fallback when absent; Tasks enablement/fallback preferences remain in `pi-tasks.json`, while plans remain in session entries. These companion files are not part of the workspace Save transaction. Ask reads its saved visuals when a question opens but keeps ownership of answer and focus behavior. `/egregore` can temporarily dress the input when Egregore is off and restores its prior appearance on closing. See [FOOTER.md](FOOTER.md) for the controls and limits, and [the surface contract](../../docs/SURFACE-WORKSPACE.md).

The former standalone `/composer-preview` synthetic screen was retired because its fabricated Composer/footer layout no longer represents the live workspace. Do not reuse its fixed-cell renderer or sample composition for new Composer work. Use the live native-editor preview in `/egregore` for appearance edits; test animation on the real Composer frame.

## Commands and preferences

| Command | Effect |
| --- | --- |
| `/composer` | Open Composer's appearance picker |
| `/composer on`, `/composer off` | Enable Composer or restore the native shell |
| `/composer motion work`, `/composer motion off` | Animate only for real work, or disable Egregore's motion |
| `/composer theme on`, `/composer theme off` | Apply or release the matching runtime palette |
| `/composer icons nerd`, `/composer icons plain` | Egregore header/fallback glyphs; frame/Sent metadata icons use `/egregore` |
| `/composer output raw`, `/composer output readable` | Change expanded tool-card output for this session |
| `/egregore` | Customize frame, footer, Tasks, Ask and Transcript visuals; narrow layouts show Rooms… and Ctrl+R opens all rooms |
| `/activity` | Browse recent session updates and inspect their quest or task sources |
| `/dictate` | Toggle microphone dictation from the keyboard; the fullscreen bottom-rail mic does the same |
| `/sounds [on\|off\|test\|question]` | Session-only native notification controls and previews; macOS |
| `/recaps on`, `/recaps off`, `/recaps status` | Opt-in additional activity inference; also discoverable through `/composer` → Activity recaps |

Supported Composer preferences are `enabled`, `look: "composer"`, `motion: "work" | "off"`, `icons`, `details` and `theme`. They are persisted in the configured Pi agent directory, not in the repository. `pi-egregore.json` is the visual settings authority (with read-only legacy fallback). Disabling Composer does not turn off Tasks or erase visual preferences. Manual edits to Pi resources require `/reload` or a cold start.

## Optional activity recaps

Recaps are **off by default** when `pi-recaps.json` is absent or invalid. `/composer` → **Activity recaps** explains the processing scope and asks for confirmation before enabling. `/recaps on` is an explicit enable command; `/recaps off` cancels queued/in-flight requests. These controls save immediately and separately to `pi-recaps.json`, not through workspace Save. Existing explicit enable/disable preferences are preserved.

When enabled and the target OpenAI Codex/OAuth model is available, a tool-bearing TUI run can send bounded request/reply/tool evidence for an additional generated recap. This uses subscription resources; there is no daily cap or automatic retry. Redaction is not a privacy guarantee. `/recaps status` reports the model, queue and saved state. Recap output is not verification or proof of task completion.

## Lifecycle and limits

Egregore uses one scheduler for real run transitions and its recorded response/idle clock. Actual blocking prompts pause both active-run clocks. Passive Tasks/posted-question browsing suppresses motion without pausing independent work; failed and stopped runs remain labeled, and unfinished saved runs get no fabricated completion. Time metadata follows the active session branch. The footer owns bounded local Git checks. Noninteractive Pi modes do not mount the terminal UI or start its render timers.

The transcript adapters and paint guard use guarded native component internals that arrived in Pi 1.0 and remain the shape Pi 1.3.0 renders; review compatibility after a host upgrade. Egregore must not silently replace another custom editor/footer owner. Pi still owns streaming Markdown, retry and compaction content, selection, mouse dispatch and terminal painting. Physical IME candidate windows, font/color legibility, motion perception and authenticated tool flows cannot be proven by unit tests or tmux captures; see [ACCEPTANCE.md](../../docs/ACCEPTANCE.md).

Key source boundaries: `index.ts` is the entry; `workspace-runtime.ts` owns session UI lifecycle; `dictation.ts` owns mic capture, local transcription and its consent-gated model download, with no preference file of its own; `surface-lifecycle.ts` keeps disposed mounts inert; `composer-controls.ts` owns `/composer` and `composer-preferences.ts` owns its compatible read/explicit-save authority; `state.ts` owns the response clock and validated Composer preferences; `ui.ts`, `composer-style.ts`, `composer-theme.ts`, `composer-palette.ts` and `composer-editor.ts` adapt the native Composer; `dock.ts` hosts sourced dock rows; `footer.ts`, `footer-state.ts`, `footer-settings.ts` and `appearance*.ts` own the transactional workspace; private `workspace-*-room.ts` builders define controls, `workspace-setting-layout.ts` owns wording/columns and `workspace-general-preview.ts` owns sample messages. `native-message-adapter.ts` guards read-only native facts for chat and grouped tools with native fallback; `pi-agent-contracts` (dependency) defines the optional data protocol. `pi-embeddable-frame` remains a passive library, not a global UI override.

The [all-settings review](../../docs/SETTINGS-REVIEW.md) records each control's purpose, safe demonstration and persistence scope. Unknown Tasks section/presentation versions now fail before normalization. A fresh Pi process is recommended after this module refactor; no live preferences were changed.

For this checkout, run `npm test`, `npm run typecheck --workspace=pi-ask` and `npm run pack:check` from the repository root. The root suite smoke test packs the private package, loads it with a real Pi host in an isolated agent directory and checks for duplicate registrations. Historical preset and gallery tests were removed with their source; the retained Egregore/Tasks/Ask/Frame suites cover the supported surfaces.
