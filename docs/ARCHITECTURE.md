# Architecture and ownership

This document describes the current ownership boundaries. The repository root is now a **private installable Pi package**, but a shared visual-customization API has not yet been implemented.

```text
Tasks plan/history state ── versioned data-only dock events ──> Home UI host
Ask question/answer state ── owns temporary input surface
Home layout + appearance preferences ──> Frame rendering primitives/presentation
Tasks native fallback ──> shared task-frame adapter ──> Frame
Ask question surface ──> package-local Frame loader ──> Frame
```

- **Frame** (`packages/pi-frame`) owns `frameRows`, `frameRail`, `paintFramePerimeter`, `statusPreset`, presentation rules, and the optional motion controller. Its optional `presentationRows` styles title/summary/hint rail labels bold while leaving ordinary body rows alone; consuming surfaces choose their own label colors. It does not infer task states, create timers by default, or replace Pi components globally. Public imports use `/primitives` and `/presentation`.
- **Home** (`extensions/pi-home`) owns its editor decoration, transcript adapters, `/workspace` interaction, preview transaction, and UI lifecycle. `appearance.ts` validates versioned input settings; `appearance-render.ts` lays out the input/footer. `footer.ts` writes versioned `pi-workspace.json` and reads `pi-footer.json` only as a legacy fallback, including Tasks *presentation*, Ask visuals and Home's versioned `transcript` chat/tool section, while Ask itself validates/reads its own section. `pi-home.json` separately owns Home look/enabled preferences. This suite's Home entry includes Ask's source for the integrated editor.
- **Tasks** (`extensions/pi-tasks`) owns the `tasks` tool, `/tasks`, plan state/history and its independent no-Home widget. `pi-tasks.json` owns its enablement/fallback preferences. Session entries, not frame settings, store branch-sensitive task information. Tasks owns accepted-request records (immutable source/acceptance, explicit supersession, task links), their structural coverage checks, and its one-pass `agent_before_settle` checkpoint for agent-edited plans, including apparently closed task lists. The checkpoint asks the model to compare conversation requests against both the ledger and tasks; it is one hidden, bounded reminder with at most one additional model request per run, never automatic outcome mutation, broader authorization, or a loop. Uncovered requests and cancelled linked tasks prevent plan closure/agent archival; the read-only Q coverage view lives in Tasks, not Home. There is no new appearance preference. Payload version 3 retains the plans-v2 entry key so older readers fail closed; legacy records migrate without invented requirements. Semantic coverage and request interpretation remain model judgments. Settled reconciliation entries are filtered from later model context. Home merely displays sourced state.
- **Ask** (`packages/pi-ask`) owns the question tools, answer semantics, custom input, focus, versioned visual parser and synthetic shell preview. It reads the `ask` visual section of `pi-workspace.json` (or legacy `pi-footer.json`) once on opening a question, using the old `questionLabels` value only when no section is saved; it works without Home.
- **Shared adapters** (`lib/`) hold the versioned Home/Tasks dock event protocol, shared task frame, and local Frame reload adapter. Ask has a package-local reload adapter so it can remain independently installed.

Pi's public extension/TUI APIs and host-provided packages are the foundation. Home's Pi 1.0 transcript adapters also use guarded native internals; recheck them after host upgrades. Keep the native editor, Vim instance, draft, IME cursor, mouse selection and tool execution independent of visual styling. Support non-TUI modes without starting visual timers.

## Harness guidance and evaluation

Tasks owns evidence-based stopping guidance through existing `doneWhen` and requirement acceptance fields. Its unchanged one-shot checkpoint distinguishes missing work, record-only updates, unresolved evidence/blockers, and unauthorized optional improvements; it still checks original conversation coverage even for closed plans. Ask owns shared answer-handoff guidance for both question tools: preserve notes/caveats, drop stale questions, and leave skips/unknown approvals unresolved. It does not automatically mutate Tasks or require Tasks to be installed. These are guidance contracts, not semantic guarantees or new lifecycle/schema behavior.

`eval/harness/` is a development-only, opt-in comparison kit with synthetic scenarios, a local artifact verifier, validated paired review records, and deterministic tests. It is not registered as an extension or packaged as a runtime component. No telemetry, session ingestion, paid model execution, or context-management policy is added. See `eval/harness/README.md` from the repository root for authorization, isolation, provenance, and evaluation limits.

## Intended customization boundary

Grow `/workspace` into an opt-in **surface workspace** without making Frame a global layout manager. A surface adapter should define stable element IDs, supported slots, defaults, semantic state facts, collision priorities, preview samples and validated versioned preferences. A shared interaction layer can provide keyboard/mouse selection, live previews, Save/Undo/Discard and rollback. The surface still owns content, input, hit targets, lifecycle, and redraw. Preview facts must be explicitly labeled and never written to tasks, answers, drafts or timestamps.

Start by extracting only proven common mechanics. Composer has six rail positions *and* footer rows; a question has a replacement input surface; Tasks has a body and overview; transcript tool cards can be self-rendering. Do not pretend every surface has the same slots. Give each screen a keyboard path, responsive/narrow fallback, theme contrast and reduced-motion safety.

## Dependency and installation rules

The private root `pi-workspace-suite` manifest explicitly lists `extensions/pi-home/index.ts`, `extensions/pi-tasks/index.ts` and `packages/pi-ask/extensions/questions.ts`, once each. The packed root bundles only `pi-embeddable-frame` under its own `node_modules`; Frame registers no extension. The host packages actually imported by suite sources (`@earendil-works/pi-coding-agent`, `@earendil-works/pi-tui`, `@earendil-works/pi-ai`, `typebox`) are peers, not bundled runtime dependencies. Frame and Ask retain their separate versioned package manifests, but must not be loaded a second time alongside the suite. Keep one authoritative source file for each module. Packed install, a real Pi RPC cold-start, repeat loader tests and an interactive `/reload` now pass. Live settings load this checkout once. The older personal Home directory and its exclusion were removed at the user's request; the older personal Tasks directory is still excluded. The original migration backup records the earlier switch, not this cleanup. Physical IME, human visual/motion review, real drag selection and authenticated turns remain unverified. See [migration](MIGRATION.md) and [acceptance](ACCEPTANCE.md).
