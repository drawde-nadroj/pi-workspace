# Architecture and ownership

This document explains how the suite composes one experience without merging domain-state or native-input ownership. For user procedures and lookup, start at [the documentation index](README.md). It describes the current ownership boundaries. The repository root is now a **private installable Pi package**, but a shared visual-customization API has not yet been implemented.

```text
Quests cross-session pursuits ── sourced Tasks links + recorded progress
Quests + Tasks activity facts ── suite-local events ──> Egregore session activity
Tasks plan/history state ── versioned data-only dock events ──> Egregore UI host
Ask question/answer state ── owns temporary input surface
Egregore layout + appearance preferences ──> Frame rendering primitives/presentation
Tasks native fallback ──> shared task-frame adapter ──> Frame
Ask question surface ──> package-local Frame loader ──> Frame
```

- **Frame** (`packages/pi-frame`) owns `frameRows`, `frameRail`, `paintFramePerimeter`, `statusPreset`, presentation rules, and the optional motion controller. Its optional `presentationRows` styles title/summary/hint rail labels bold while leaving ordinary body rows alone; consuming surfaces choose their own label colors. It does not infer task states, create timers by default, or replace Pi components globally. Public imports use `/primitives` and `/presentation`.
- **Egregore** (`extensions/pi-egregore`) owns its editor decoration, transcript adapters, `/egregore` interaction, preview transaction, and UI lifecycle. The six top sections (Input, Tasks, Ask, Transcript, More settings, General) own Tab/Shift-Tab navigation; Input properties stay within its section. Egregore alone owns the view-only advanced-control disclosure, contextual help and preview labels; none of these writes a preference or changes Ask/Tasks semantics. The standalone fixed-cell `/composer-preview` demo was retired: its fabricated footer/layout was not a source of truth for the live Composer. Composer appearance previews use the native editor in `/egregore`; motion prototypes must target the live frame rather than resurrecting that renderer. Before writing shared visual preferences, Egregore rejects stale on-disk workspace/legacy snapshots and unsupported Composer appearance versions (an optimistic check, not a cross-process lock). `appearance.ts` validates versioned input settings; `appearance-render.ts` lays out the input/footer. `footer.ts` writes versioned `pi-egregore.json` and reads `pi-workspace.json`, then `pi-footer.json`, only as legacy fallbacks, including Tasks *presentation*, Ask visuals and Egregore's versioned `transcript` chat/tool section, while Ask itself validates/reads its own section. `composer-controls.ts` owns `/composer` operational controls; `composer-preferences.ts` reads/writes `pi-composer.json`, falling back read-only to `pi-home.json` when the new file is absent. `workspace-runtime.ts` owns mounting and teardown through per-mount `surface-lifecycle.ts` scopes. The root manifest separately loads Ask; the appearance editor imports only its display-only preview/parser, not its question runtime.
- **Tasks** (`extensions/pi-tasks`) owns the `tasks` tool, `/tasks`, plan state/history and its independent no-Egregore widget. `pi-tasks.json` owns its enablement/fallback preferences. Session entries, not frame settings, store branch-sensitive task information. Tasks owns accepted-request records (immutable source/acceptance, explicit supersession, task links), their structural coverage checks, and its one-pass `agent_before_settle` checkpoint for agent-edited plans, including apparently closed task lists. The checkpoint asks the model to compare conversation requests against both the ledger and tasks; it is one hidden, bounded reminder with at most one additional model request per run, never automatic outcome mutation, broader authorization, or a loop. Uncovered requests and cancelled linked tasks prevent plan closure/agent archival; the read-only Q coverage view lives in Tasks, not Egregore. There is no new appearance preference. Payload version 3 retains the plans-v2 entry key so older readers fail closed; legacy records migrate without invented requirements. Semantic coverage and request interpretation remain model judgments. Settled reconciliation entries are filtered from later model context. Egregore merely displays sourced state.
- **Ask** (`packages/pi-ask`) owns the question tools, answer semantics, custom input, focus, versioned visual parser and synthetic shell preview. It reads the `ask` visual section of `pi-egregore.json` (or legacy `pi-workspace.json`, then `pi-footer.json`) once on opening a question, using the old `questionLabels` value only when no section is saved; it works without Egregore.
- **Shared contracts** (`packages/pi-agent-contracts`) hold the versioned Egregore/Tasks dock and Ask posted-question event protocols with their validators and layout helpers. **Shared adapters** (`lib/`) hold the shared task frame and local Frame reload adapter. Ask has a package-local reload adapter so it can remain independently installed.

Pi 1.3.0 is the minimum supported host and the CI-verified baseline; CI also runs the current Pi 1.4.0 release, and runtime host peers stay `*` per Pi's package contract. Ask's development host dependencies are pinned to 1.3.0. Ask preserves the renderer-owned fake-cursor protocol introduced in Pi 1.2, including hardware-cursor suppression, and strips input-supplied cursor markers. Pi's public extension/TUI APIs and host-provided packages are the foundation. Egregore's Pi 1.0 transcript adapters also use guarded native internals; recheck them after host upgrades. Keep the native editor, Vim instance, draft, IME cursor, mouse selection and tool execution independent of visual styling. Support non-TUI modes without starting visual timers.

## Quests landscape

Quests (`extensions/pi-quests`) owns the `quests` tool, native `/quests` browser, and a cross-session SQLite journal under the Pi agent directory. Sources, home workspace, reach, linked paths, buffered exploratory questions, evidence and revisioned event snapshots belong to Quests. Its native dialogs are the visual adapter and standalone fallback; there is no new appearance settings authority. Egregore identity is the resolved working directory. Explore in chat sends an explicit conversational inquiry, not implementation permission; Keep for later only records interest. Explicit conversational pursuit can also be recorded against a matching user-message ID and quote without sending work. Optional goals, progress and Tasks references extend existing records; completion requires a goal and fresh evidence. Tasks references retain a dated snapshot for other sessions and resolve against the current branch when available. Quests supplies conversational guidance without a settlement continuation. Tasks' completion review keeps the main response primary; there is no mandatory Where next handoff. Tasks remains the execution owner and Ask remains the approval/question-delivery owner. See the [Quests guide](../extensions/pi-quests/README.md) for first-slice limitations.

Quests' `continuity.ts` owns typed, source-linked context statements and bounded resume projection. `store.ts` commits immutable statements/corrections and idempotent snapshot updates transactionally; `context.ts` reads only the current branch's Tasks/Ask owners, with Ask loaded lazily. `record` source descriptions are agent reports, while optional entry IDs validate existence. `sync` retains answer/caveat/consequence snapshots without applying answers or mutating Tasks. Changed linked snapshots flag the next move for reassessment. `resume` labels current-branch versus historical projections and caps orientation at 16,000 characters. Branch-local `pi-quests:focus-v1` selects one pursuit for the existing before-run guidance; it is not pursuit acceptance and adds no continuation or background work. Full records and correction history remain available. Existing journals accept additive fields without an eager rewrite; oversized records fail transactionally rather than dropping history.

Quests' `handoff.ts` resolves read-only presentation snapshots and renders `quests present` through Pi's public tool-renderer API. Inline paths remain conversation-only; referenced paths retain journal state and source. The shared Frame primitive supplies jade chrome; Quests owns the Deepen/Connect labels, gold connection accent, wrapping and compact/expanded text. The operation does not create journal events, send user messages or request continuation. The full handoff is for an explicit request to explore directions. A compact unframed green `Possibility` style accepts one path, while `possibility-markdown.ts` uses the optional public Markdown transformer to style an explicitly marked standalone assistant title within the main response. It leaves stored/model text unchanged, skips code/quoted examples and other message roles, and keeps readable Markdown on hosts without the capability. No native assistant-component monkey patch or suggestion classifier is installed.

Quests' optional `intent` metadata distinguishes keep/saved, explore/active and make/active with sourced conversational requests. Provenance and state consistency are validated; consent interpretation remains agent judgment, and make is not renewed authorization. Exact offers use an immutable original-input fingerprint for retry reuse; old records remain readable without eager migration. Possible directions is a counted view of linked offered/saved quests, while other relationships remain Connections. It does not introduce a second hierarchy store or extra activity surface. See [side-exploration assessment](SIDE-EXPLORATION.md) for the deferred conversation mechanism.

Tasks' `attention-dock.ts` owns compact attention grouping from task state and Ask projections. It prioritizes answerable questions and distinguishes delivery/application stages. Both dock hosts display those same rows; Egregore owns clipping and appearance, not inferred readiness or question state.

## Collaboration language and readiness

Tool descriptions and prompt guidelines steer a shared flow without merging state owners: Quests holds exploratory questions and current `nextMove`; Tasks records concrete work, dependencies and optional blocker responsibility/release conditions; Ask delivers input and decisions, then asks the agent to apply caveats and reassess linked work. `blockerOwner` and `unblockWhen` extend task records additively as descriptive metadata. They do not grant permission or automatically transition tasks. Legacy records remain readable with unspecified responsibility. Linked Quest task snapshots retain these facts when present.

Tasks and standalone Ask attention distinguish user input, deferred perspective, pending delivery and agent follow-up. Delivered answers remain unresolved until applied or explicitly dispositioned; that is not a request for the person to answer again. Quests' counted disclosures are read-only presentation state, with current context separate from historical detail. Agents maintain the accuracy of next moves and blocker conditions; no new background monitor or settlement loop is introduced.

## Platform compatibility boundary

The supported baseline is Pi 1.3.0 with Node.js 22.23.2; CI exercises Windows, Linux and macOS. Windows fixture links use junctions, captures use OS temporary directories, and the packed smoke test launches the selected host's JavaScript CLI rather than shell shims. Footer shutdown detaches UI synchronously, aborts Git polling and awaits actual child-process closure before returning. Bounded fixture cleanup retries handle residual filesystem locks.

pi-vim 0.14.2 owns its hard-coded undo dispatch. The supported Windows setup adds a user-configured `ctrl+-` undo alias alongside `ctrl+z`; integration fixtures use that same configuration and separately reproduce the unconfigured upstream failure. Egregore does not own or silently change native keybindings, Vim undo state or the Vim implementation. See [installation](INSTALL.md#native-windows-supported-setup-and-smoke-test).

## Glanceable activity ownership

Egregore's `session-activity.ts` consumes data-only `pi-workspace:session-activity-v1` events from Quests and Tasks. It persists deduplicated branch-local entries, displays up to three recent updates above the Composer and exposes `/activity` to inspect source records. The recent view is bounded to 200 entries; persisted session entries remain intact. It adds no timer, model call or editor replacement. `sessionActivity` and `activityColor` belong to `pi-egregore.json`, controlled by General in the existing Egregore preview/Save/Discard/Undo transaction. Optional sibling modules load only when inspecting sources, preserving standalone Egregore startup. This event history is distinct from timing strips and opt-in generated recaps.

Egregore owns `composer-ember.ts`, a deterministic five-cell status marker rendered by both Composer rail paths. Five fixed grid scenes are selected from the current appearance state: figure-eight (thinking), conveyor (responding), twin counter-orbits (tools), collapse (compacting) and serpentine (working). Real tool-start events supply a coalesced transient response timestamp; the existing Egregore clock schedules redraws. No new timer, saved setting, native-input adapter, randomness or Frame behavior is introduced. Composer perimeter motion is retired; ordinary typing leaves the marker at normal strength, dialogs/motion-off stop it, and inactive states are static. Tool names yield before state text in narrow slots. `composer-title.ts` supplies the static session badge for default and configured layouts. It reuses the contrast-aware background painter without changing title data, configured foreground or placement. Input-rail rendering respects per-element weight rather than forcing all labels bold.

Dictation is a Egregore-owned operational control, not an appearance feature: `dictation.ts` owns the phase machine, the single `ffmpeg` capture child, the `whisper-cli` run, and the consent-gated model download, while `workspace-runtime.ts` owns its lifecycle, `/dictate` and the idle repaint that keeps `REC <n>s` moving. `composerBottomRail` renders its label from the same builder both editor paths use, and each wrapper hit-tests only the rail row it painted, so a click never moves keyboard focus or reaches the native text coordinates. Nothing is persisted: no preference file, no session entry. Rendering is gated on host-dispatched pointer clicks (viewport TUI) and a 40-column floor; the regular TUI keeps `/dictate`. Frame and the settings transaction are untouched.

Egregore also owns native notification playback in `sounds.ts`. Its runtime observes `agent_settled` after a started successful run (unless settlement is aborted), and blocking Ask prompt openings deduplicated by tool-call ID. It does not change Ask answers or Tasks state. `/sounds` is a session-only operational control outside the appearance transaction; macOS, Windows and Linux default on. Portable 16-bit PCM WAVs use `afplay`, Windows PowerShell calling checked WinMM `PlaySoundW`, or Linux `pw-play`/`paplay`/`aplay`. Windows uses synchronous filename playback with `SND_NODEFAULT` and rejects a FALSE result; unlike SoundPlayer.PlaySync, it cannot discard backend rejection. Linux advances only on missing executables, not player failures. Paths remain argv/environment data, child processes use no shell, and teardown cancels active playback and pending fallback. Separate asset licensing, source hashes and conversion provenance ship alongside the assets.

Tasks still owns plan state and publishes data-only snapshots. Egregore's `task-presentation.ts` applies steady active-row emphasis and, under Changes motion, one short highlight for changes in active ID or completed/cancelled counts. Fresh defaults select Changes at 1200 ms; saved settings are preserved. Its controller resets when hidden to avoid replay on remount. The standalone `/tasks` browser owns its matching bold active title and soft tint, distinct from selection. It keeps its existing navigation and working/paused semantics. Work-remaining/request-coverage semantics are unchanged.

## Auxiliary recap authority

Egregore's optional recaps use `pi-recaps.json` and default off on missing/invalid configuration. `/composer` routes to the owner-native recap controls; `/recaps` saves separately and immediately. Opt-in discloses additional bounded OpenAI Codex/OAuth inference and subscription-resource use; off cancels queued/in-flight work. This is not part of the appearance transaction or task verification.

## Native Tasks–Ask thread

Tasks exposes **Work / Requests / Questions**. Work and request state remains Tasks-owned; question state remains Ask-owned. `pi-agent-contracts/posted` is a passive version-1 data contract (question snapshots/open requests, Tasks link catalogue, non-blocking interaction tags), not a shared state database or renderer. Optional bounded catalogue titles/task names improve read-only context, and `attentionHosted` is distinct from link availability so hiding Tasks permits Ask's fallback cue. Legacy catalogues remain supported. Response kind is displayed separately from delivery phase; correction guidance preserves original records and does not promise to reverse delivered effects. Ask stays independently installable; Tasks works when Ask is not loaded and shows an unavailable inbox. Egregore owns the attention presentation and clock interpretation; Frame remains passive.

Synchronous Ask owns Regenerate (`Ctrl+R`) in single-question forms and batches with unanswered questions, including fresh batches. It returns revision context without treating a single-question draft as an answer; batch answers and notes remain context. Posted forms explicitly disable this action because their durable response protocol supports clarification, not regeneration. No Egregore setting or Frame behavior changes.

Ask's `/questions` inbox uses `postedInboxUI` inside the same `frameQuestion`/appearance adapter as its answer form, with native SelectList navigation, bounded height, stable question IDs and readable lifecycle labels. Selection opens the existing TabbedQuestions form. The posted validator shares the form's one-based option identity; question indices remain zero-based. The inbox participates in the existing dialog lock and session-close lifecycle rather than using a separate generic selector.

Ask's `question_queue` tool persists version-1 branch-local posted-question records under `pi-ask:posted-v1`. `/questions` is its standalone entry; unresolved projections lead the Tasks work list. The TaskPanel stays mounted under a raised Ask overlay. Ask reuses its existing native answer/review machinery and reads the existing Ask appearance/density once on opening. Nested Escape follows review/note/custom/clarification Back/Discard semantics; outer Escape preserves unsubmitted drafts, including clarification buffers. Urgency-only changes refresh displayed context without losing input; definition/session changes still reject submission. Explicit Submit records a response and queues Pi steering. Delivery is acknowledged only when the original submission is included in a model-context event. Application is an explicit agent report with consequence, never automatic task mutation. Stale revisions/session interactions fail closed. Withdrawal and replacement preserve provenance and never imply consent. Interrupted submissions are not automatically retried.

Tasks enforces only **linked agent task starts/completions** against unresolved projections (deferred questions become blocking through an Ask-owned needed-now transition at that boundary) and blocks agent archival with unresolved linked questions. This is not a generic tool/side-effect permission system. Independent authorized work can continue. Existing synchronous Ask remains the immediate blocking interaction. User task edits retain their own precedence. The Egregore overview's optional `questions` counts are validated separately from task progress; they do not manufacture task blockers or verification. `pi-workspace:interaction:v1` tags Tasks browsing and posted Ask as input-owning but non-blocking; Egregore still suppresses motion while focused dialogs own input, while tracking real independent work. Synchronous Ask and untagged blocking prompts still pause active time.

Historical tool results own post/disposition/application cards; custom submission messages own submitted-response cards; one immutable custom entry owns the delivery receipt. Defaults use progressive disclosure and readable wording. Tasks' display-only `transcript.ts` adapter owns neutral work titles with small status-colored glyphs, grouped request headings, bounded prose and exact-source/criterion disclosure. Shared coverage qualifications remain in the body rather than only in a clipping-prone frame rail; no record, outcome or appearance setting changes during rendering. The native browser and transcript share Tasks' `typography.ts` vocabulary; browser selection remains a separate caret/background, and grouped short-label details use the same bounded reading measure. Overview layout and question semantics are not replaced by this presentation grammar. Existing `/egregore` Tasks, Ask and Transcript boundaries remain authoritative—no new settings file or cross-file transaction. The Tasks room styles the persistent Egregore overview, Ask styles its shell, and Transcript's eligible adapters do not take over self-rendering Ask/Tasks bodies. No new live preference or native draft is used for demonstration.

## Harness guidance and evaluation

Tasks owns evidence-based stopping guidance through existing `doneWhen` and requirement acceptance fields. Its unchanged one-shot checkpoint distinguishes missing work, record-only updates, unresolved evidence/blockers, and unauthorized optional improvements; it still checks original conversation coverage even for closed plans. Ask owns shared answer-handoff guidance for both question tools: preserve notes/caveats, drop stale questions, and leave skips/unknown approvals unresolved. It does not automatically mutate Tasks or require Tasks to be installed. These are guidance contracts, not semantic guarantees or new lifecycle/schema behavior.

`eval/harness/` is a development-only, opt-in comparison kit with synthetic scenarios, a local artifact verifier, validated paired review records, and deterministic tests. It is not registered as an extension or packaged as a runtime component. No telemetry, session ingestion, paid model execution, or context-management policy is added. See `eval/harness/README.md` from the repository root for authorization, isolation, provenance, and evaluation limits.

## Native copy feedback

Egregore's private `copy-flash.ts` adapter frames only Pi 1.0's exact fullscreen `Copied!` success row with passive Frame primitives. Pi owns flash state, clipboard operations, expiry and top-right composition; Egregore owns only this reversible render decoration while Composer is enabled. No new preference or input handler is introduced. Other notices, unsupported shapes, narrow widths and insufficient screen height retain native rendering. Teardown restores only the adapter's own patch and leaves retained wrappers inert.

`copy-selection.ts` owns the private fullscreen copy adapter and a weak, per-component record of the latest supported frame geometry. Chat, grouped tools and ordinary/web tool adapters register their rendered rows; Frame remains passive and unchanged. The copy adapter follows the native scroll-content Container mouse layout without rerendering, validates exact source rows and native extraction, then excludes only registered rails, sides and added padding. It preserves literal pipes and border-like content and leaves regular mode, fixed docks, self-renderers and unsupported/stale layouts native. No clipboard backend, selection input, preference file or timer is replaced. Copy feedback uses an achromatic light/dark border and ordinary theme text instead of accent/success colors.

## Egregore selection adapter

Egregore owns persistent selection and optional static hover inspection in the four `/egregore` appearance rooms. `preview-selection.ts` adapts synthetic Tasks/Ask/Transcript rows using actual rendered rectangles and discovered perimeters; it never opens Ask, edits Tasks or writes preferences. Native Composer retains `appearance-render.ts` and its existing editor instance. Inspection/focus are ephemeral; only accepted property edits enter the bounded Undo/Save transaction. Selection backgrounds track the actual foreground SGR color so user identity, custom colors and failed statuses remain unchanged and readable. Fixed preview labels can remain inspectable without being highlighted as affected by a control. Input, hover and pulse resources clear on the documented lifecycle boundaries.

The proposed central Transcript catalogue covers codemode, edit/write, web results and extension-submitted messages through owner-approved adapters, not a universal renderer or tool interception. Its scope and prospective contract live in [the surface specification](SURFACE-WORKSPACE.md#proposed-transcript-catalogue); there is still no public registration API or duplicate preference authority.

## Implemented private refactors and registry boundary

1. Egregore's private `workspace-input-room.ts`, `workspace-message-rooms.ts`, `workspace-preference-rooms.ts` and existing `task-settings.ts` build controls through `workspace-room-types.ts`. `footer-settings.ts` retains the single draft, Undo/Save/Discard transaction, navigation, hit testing, audition and lifecycle. `workspace-setting-layout.ts` owns display-only vocabulary/columns; `workspace-general-preview.ts` owns explicitly synthetic name/spacing examples. The pure Egregore-owned `message-spacing.ts` applies the existing density to live user/assistant bodies and General/Transcript samples: Compact adds no edge rows, Spaced adds one above and below. `sent-messages.ts` normalizes only native padding and translates mouse coordinates; internal content gaps and native fallback remain intact. They do not centralize Ask/Tasks domain state or create a public registry.
2. `native-message-adapter.ts` supplies read-only typed facts for `sent-messages.ts` and `grouped-tools.ts`. It guards native methods, private-field shapes, content/call records, streaming and positive creation timestamps on every read. Unsupported/throwing or drifted shapes use native rendering; disposal restores only owned patches. Egregore's full entry now passes strict typing; the four previously recorded native-field diagnostics are resolved. Native classes remain host-owned, not a new public dependency contract.
3. Choice audition clones visual preferences or uses a synthetic state, separate from the accepted draft, real run and Undo. Current-value restoration avoids introducing default sections into an otherwise unchanged candidate. Menu geometry is stable within a terminal size; blur/resize/invalidation/close restore audition. Save accepts only the draft. Egregore still owns one settings file transaction; companion Egregore/Tasks preferences save separately.
4. `loadWorkspacePrefs` rejects unknown Tasks section/presentation versions before `footerPrefs` can normalize them away. Ask/Transcript retain their existing read-only/Save-blocking behavior. No schema version or live settings file is migrated by this change.
5. Prove representative owner-approved tool/message adapters before exposing the proposed catalogue registration contract. Keep runtime preference and theme authorities singular; adapter discovery must not imply permission to intercept execution or replace self-rendering content.

The first two refactors and all-settings improvements were explicitly authorized and implemented. The larger registry/front-door remains proposed. See [the complete settings review](SETTINGS-REVIEW.md) and [fresh acceptance evidence](ACCEPTANCE.md).

## Intended customization boundary

Grow `/egregore` into an opt-in **surface workspace** without making Frame a global layout manager. A surface adapter should define stable element IDs, supported slots, defaults, semantic state facts, collision priorities, preview samples and validated versioned preferences. A shared interaction layer can provide keyboard/mouse selection, live previews, Save/Undo/Discard and rollback. The surface still owns content, input, hit targets, lifecycle, and redraw. Preview facts must be explicitly labeled and never written to tasks, answers, drafts or timestamps.

Start by extracting only proven common mechanics. Composer has six rail positions *and* footer rows; a question has a replacement input surface; Tasks has a body and overview; transcript tool cards can be self-rendering. Do not pretend every surface has the same slots. Give each screen a keyboard path, responsive/narrow fallback, theme contrast and reduced-motion safety.

## Dependency and installation rules

The private root `pi-egregore` manifest explicitly lists `extensions/pi-egregore/index.ts`, `extensions/pi-tasks/index.ts`, `packages/pi-ask/extensions/questions.ts` and `extensions/pi-quests/index.ts`, once each. The packed root bundles `pi-embeddable-frame` and `pi-agent-contracts` under its own `node_modules`; neither library registers an extension. The host packages actually imported by suite sources (`@earendil-works/pi-coding-agent`, `@earendil-works/pi-tui`, `@earendil-works/pi-ai`, `typebox`) are peers, not bundled runtime dependencies. Frame and Ask retain their separate versioned package manifests, but must not be loaded a second time alongside the suite. Keep one authoritative source file for each module. Packed install, a real Pi RPC cold-start, repeat loader tests and an interactive `/reload` now pass. Live settings load this checkout once. The older personal Home directory and its exclusion were removed at the user's request; the older personal Tasks directory is still excluded. The original migration backup records the earlier switch, not this cleanup. Physical IME, human visual/motion review, real drag selection and authenticated turns remain unverified. See [migration](MIGRATION.md) and [acceptance](ACCEPTANCE.md).
