## Cross-platform notification sounds (2026-10-25)

Implemented in the `drawde-nadroj/cross-platform-sounds` worktree, based on `3b0046c` plus the isolated sound changes. The original checkout and its unrelated work were left untouched; no live Pi settings were changed.

- **Automated:** full `npm test` and `npm run pack:check` passed locally on macOS. Workspace includes regressions for final-settlement notification (including late abort), question deduplication, mute, noninteractive silence, missing-player fallback, device/permission errors, cancellation during fallback, instance reuse, safe Windows path transport, and portable WAV decoding headers. General UI fixtures explicitly mute audio rather than requiring a device.
- **macOS native smoke:** the changed module played both converted cues through `afplay`; cancellation and subsequent reuse completed successfully.
- **Linux native smoke:** Node 24.19.0 on Debian x86-64 ran the actual playback module, fell through absent PipeWire/PulseAudio executables, and completed both cues through ALSA `aplay` 1.2.14. Cancellation and reuse also passed. The player and libasound were extracted into a disposable directory, not installed system-wide. A temporary ALSA null PCM sink exercised actual player/decoder execution; this does **not** establish audible hardware output or PipeWire/PulseAudio server connectivity.
- **Windows CI and corrected acceptance boundary:** [run 40185777184](https://github.com/drawde-nadroj/pi-workspace/actions/runs/40185777184), commit `cadc06c`, passed all four jobs: Windows, macOS and Ubuntu with the locked host, plus Ubuntu with Pi 1.4.0. The initial PowerShell/SoundPlayer test passed on Windows Server 2025 / Node 22.23.2, but this established invocation only: .NET SoundPlayer.PlaySync discards the native PlaySound Boolean result. That backend is now replaced by checked synchronous WinMM `PlaySoundW` with `SND_NODEFAULT`. The native Windows regressions require TRUE for both packaged cues from a quoted Unicode path, and require an explicit rejection for a missing asset. A missing or failing output must not count as successful playback. See the branch's CI runs for this stronger regression result.
- **Assets:** original React Bits exports were converted to standard 16-bit PCM for Windows compatibility; question attenuation is baked into the asset. Source/export hashes, conversion details and resulting hashes are recorded in bundled provenance.
- **Headless runner handling:** the stronger checked-WinMM test rejected playback on [run 40186376690](https://github.com/drawde-nadroj/pi-workspace/actions/runs/40186376690); the failure was not suppressed. Windows tests now independently enumerate native output devices. Positive playback is skipped only if that count is zero, while a separate native regression must observe rejection of both real cues on a no-device host. Rejected missing assets are always tested on Windows. A green headless job must not be presented as successful audio-output acceptance.
- **Cancellation race:** Linux CI also exposed an uncaught child error during teardown. A failing-before/passing-after regression covers repeated error delivery before process close; playback now keeps its error listener attached throughout that lifetime. Workspace and Tasks UI fixtures mute audio so they do not depend on host audio services.

Human loudness/notification preference checks, physical speaker audibility, and successful checked-WinMM playback on a Windows host with an output device remain unverified. These results are not evidence of remote-audio forwarding; sounds play on Pi's execution host. The temporary Linux smoke directory and extracted packages were removed afterward.

Both are asserted behaviours, and this increment could not verify a visual redesign in a real terminal. The private reads stay, now covered by the canary; the seam itself is exercised in `examples/minimal-plan-dock` and described in `docs/PRIMITIVES.md#host-internals`.

## Repeatable isolated review

This procedure is for source reviewers with a compatible Pi host and the checkout dependencies installed. For ordinary setup, use [Install the local suite](INSTALL.md); for a no-save keyboard exercise, use [Try a reversible preview](TRY-PREVIEW.md).

Use a **fresh, temporary** agent directory outside `~/.pi` and a throwaway project. Do not run `pi install` against your normal agent directory or start the suite alongside the older live copies. **A fresh checkout now defaults to Composer.** To review any custom saved appearance rather than only defaults, optionally copy *only* existing `pi-home.json`, `pi-workspace.json` and legacy `pi-footer.json` into the sandbox before launching Pi. The owner's `pi-home.json` selected Composer; `pi-footer.json` did not exist, so only Home was copied in the earlier comparison. Do not copy credentials, sessions, task history or a whole agent directory. For example:

```bash
cd ~/code/pi-workspace
npm ci && npm test && npm run pack:check
sandbox=$(mktemp -d)
mkdir -p "$sandbox/agent" "$sandbox/project"
# Optional: match your saved appearance without changing live Pi.
for name in pi-home.json pi-workspace.json pi-footer.json; do
  if test -f "$HOME/.pi/agent/$name"; then
    install -m 600 "$HOME/.pi/agent/$name" "$sandbox/agent/$name"
  fi
done
PI_CODING_AGENT_DIR="$sandbox/agent" PI_OFFLINE=1 pi install "$PWD"
cd "$sandbox/project"
PI_CODING_AGENT_DIR="$sandbox/agent" PI_OFFLINE=1 pi --offline --no-session \
  --no-context-files --no-skills --no-prompt-templates --no-themes --no-approve \
  --use-theme dark
```

Do not submit agent prompts during the appearance review. Offline mode disables automatic network activity; it is not an OS permission/network sandbox. No model sign-in is necessary to inspect `/workspace`. Test its six sections (Input, Tasks, Ask, Transcript, More settings and General), use keyboard and fullscreen mouse where available, change a visual control, Undo, Discard, Save, then `/reload` and reopen. Repeat with `--use-theme light --tui-mode regular` and a narrow terminal. Use Pi's actual terminal to check IME, selection, theme contrast and motion. Stop Pi before deleting the **temporary** sandbox; do not remove or overwrite your live preference files. Add `pi-vim` only in the sandbox if checking that optional integration. Capture no private drafts or credentials in a committed log.

The authorized live switch and its rollback are recorded in [MIGRATION.md](MIGRATION.md). For ordinary use, finish the current Pi conversation and start Pi in a fresh process rather than relying on cached modules from this already-running session. Further rollouts or preference changes still require separate authorization.
