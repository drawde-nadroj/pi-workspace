# Migration record and rollback

**Live switch performed on 2026-10-09 after explicit user approval despite the remaining hands-on acceptance gaps.** `~/.pi/agent/settings.json` now loads this private checkout once instead of the separate Frame and Ask package entries. Two exact extension exclusions prevent the older Home and Tasks folders from auto-loading; their original files remain on disk and were also backed up. The already-running Pi session can retain the old code until it is closed; use a fresh process for the new suite. Do not load both generations concurrently. A restricted backup directory under `~/.pi/backups/pi-workspace-*/` contains the original settings, source copies, preference copies and an exact `ROLLBACK.md`.

## What changed and how to reverse it

1. The original `settings.json`, the old Home/Tasks source directories and the existing `pi-home.json` and `pi-tasks.json` were copied to a restricted backup outside discovery paths. `pi-footer.json` did not exist. No credentials or sessions were copied. The backup preserves the checkout revision and the original and new settings checksums.
2. The Frame/Ask package entries were replaced with **one** absolute suite path. Exact `-extensions/pi-home/index.ts` and `-extensions/pi-tasks/index.ts` entries prevent the old folders from loading, without moving files that an already-running Pi process may still use. A temporary agent probe first confirmed that Pi 1.0.0 applies these exclusions to auto-discovered folder entry points. All other live settings were preserved.
3. A separate fresh offline Pi process loaded one suite-owned `/home`, `/footer`, `/tasks`, `/recaps` and `/composer-preview`; its resource list included Home, Tasks, Ask and the existing pi-vim. A no-session terminal session opened Composer and `/footer` at wide/narrow sizes, opened `/tasks`, reloaded and reopened `/footer`. The live Home/Tasks preference bytes were unchanged; the absent footer preference stayed absent. This does **not** establish physical IME, human visual/motion comfort, real drag selection, authenticated turns or successful rollback of the live installation.
4. To roll back, close suite-using Pi processes and follow the checksum-guarded instructions in the backup's `ROLLBACK.md`. Restoring the old settings re-enables the separate Frame/Ask packages and the unchanged original Home/Tasks folders. Cold-start Pi; do not restore preference copies automatically or delete session data. A cold start avoids stale export maps across `/reload`. If settings have changed since this switch, manually reverse only the suite entries instead of overwriting newer changes.

The currently running Pi conversation may still hold the previous extension modules; close it and start a **new Pi process** for ordinary use. This record does not authorize publishing, further migrations or preference rewrites. The suite remains a **private local/packed package**, not a published release. Host Pi libraries remain peers; packed Frame is a declared bundled runtime dependency.
