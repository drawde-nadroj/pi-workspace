# Migration plan (not yet executed)

The private root suite is installable, but the live installation remains unchanged. `~/.pi/agent/settings.json` still names `./packages/pi-frame` and `./packages/pi-ask`; Home and Tasks are auto-discovered from `~/.pi/agent/extensions/`. Do not point live Pi at this checkout **as well** without removing or excluding those entries: duplicate tool/command registrations or competing editor/footer owners are possible.

## Planned phases

1. **Record a baseline:** run `npm ci`, `npm test`, package dry-runs and a live-terminal visual check. Record compatible Pi and dependency versions. Review this repository's tracked-file list for private data.
2. **Build the suite package (done in source):** the private root manifest lists Home, Tasks and the existing Ask entry directly. The packed root bundles only Frame as a runtime library; standalone Frame and Ask packages remain available. The package smoke test installs a tarball in an isolated `PI_CODING_AGENT_DIR`, checks that a single Pi package is declared, starts a real offline Pi RPC process to verify package-owned commands, cold-loads the three extension entry points twice with unique tool/command names, and cold-loads Tasks without Home. The existing Tasks tests cover its no-Home widget fallback. This does not exercise a real interactive reload.
3. **Compatibility (partly tested):** the packed loader test checks `/home`, `/footer`, `/tasks`, `tasks`, `ask_user_question`, and `ask_questions`. Existing unit tests cover cached/old Frame exports and standalone Tasks. Still test actual interactive `/reload`, shutdown/re-enable, both load orders, non-TUI mode and terminal visual behavior before a live switch. Preserve existing preferences at their current locations initially; validate and migrate schemas without overwriting corrupt files or plan history.
4. **Switch one live installation:** back up source and preferences outside Git; modify only Pi package/extension declarations and auto-discovery paths necessary for the switch. Verify the new commands once and confirm the old copies are not loaded. Keep a documented rollback to the previous source and settings. Do not delete sessions or task entries.
5. **Grow customization:** extract `/footer`'s reusable transaction and navigation, then add a Tasks surface page, followed by Questions and transcript frames. Keep previews display-only, with per-surface settings ownership and documented schema migrations.

## Proposed live switch and rollback (not executed)

1. Stop Pi. Back up `~/.pi/agent/settings.json`, the two original `extensions/pi-{home,tasks}/` directories, and existing `pi-home.json`, `pi-footer.json`, and `pi-tasks.json` outside the agent's discovery paths. Never delete session history or saved preference files.
2. Run `npm ci` in this checkout. Replace the two existing Frame/Ask package declarations in agent settings with **one** absolute path to this suite. Move or rename the original Home/Tasks extension directories outside `~/.pi/agent/extensions/` so auto-discovery cannot load them. Make these changes only after a terminal acceptance check and explicit authorization; avoid installing both generations concurrently.
3. Start Pi cold. Inspect the loaded-resource list and `pi list`; verify one `/home`, `/footer`, `/tasks`, `tasks`, `ask_user_question` and `ask_questions`. Verify saved settings and Tasks history, native/Vim editor, question UI, fallback without Home, narrow/wide terminals and `/reload`. Do not infer success solely from the package smoke test.
4. On any regression, stop Pi, restore the backed-up settings and extension directories, and cold-start; leave preference and session data untouched. A cold start avoids stale export maps across `/reload`.

This document does not authorize publishing, switching the live installation, or moving saved data. The suite is a **private local/packed package**, not a published release. Host Pi libraries remain peers; packed Frame is a declared bundled runtime dependency. Pin and test host compatibility before release.
