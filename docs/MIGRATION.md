# Migration plan (not yet executed)

The private root suite is installable, but the live installation remains unchanged. `~/.pi/agent/settings.json` still names `./packages/pi-frame` and `./packages/pi-ask`; Home and Tasks are auto-discovered from `~/.pi/agent/extensions/`. Do not point live Pi at this checkout **as well** without removing or excluding those entries: duplicate tool/command registrations or competing editor/footer owners are possible.

## Planned phases

1. **Record a baseline:** run `npm ci`, `npm test`, package dry-runs and the isolated terminal checklist in [ACCEPTANCE.md](ACCEPTANCE.md). Record compatible Pi and dependency versions. Review this repository's tracked-file list for private data. Automated checks and partial isolated terminal review are recorded; physical IME, visual legibility and authenticated interactions still need human observation.
2. **Build the suite package (done in source):** the private root manifest lists Home, Tasks and the existing Ask entry directly. The packed root bundles only Frame as a runtime library; standalone Frame and Ask packages remain available. The package smoke test installs a tarball in an isolated `PI_CODING_AGENT_DIR`, checks that a single Pi package is declared, starts a real offline Pi RPC process to verify package-owned commands, cold-loads the three extension entry points twice with unique tool/command names, and cold-loads Tasks without Home. The existing Tasks tests cover its no-Home widget fallback. This does not exercise a real interactive reload.
3. **Compatibility (partly tested):** the packed loader test checks `/home`, `/footer`, `/tasks`, `tasks`, `ask_user_question`, and `ask_questions`. Unit tests cover cached/old Frame exports and standalone Tasks; an isolated interactive Pi checked `/reload`, saved settings, fullscreen mouse, regular-mode keyboard, light/dark, narrow/wide and an optional pi-vim load. An authenticated turn, physical IME and human visual/selection review remain open. Preserve preferences at their current locations; versioned Ask and Transcript settings reject unknown future versions instead of silently replacing them.
4. **Switch one live installation:** back up source and preferences outside Git; modify only Pi package/extension declarations and auto-discovery paths necessary for the switch. Verify the new commands once and confirm the old copies are not loaded. Keep a documented rollback to the previous source and settings. Do not delete sessions or task entries.
5. **Grow customization (implemented in checkout):** `/footer` retains its native Composer preview and now hosts focused Tasks, Ask and Transcript rooms with synthetic display-only samples. Composer, Tasks presentation, Ask visuals and Home transcript metadata share one atomic `pi-footer.json` Save/Undo/Discard transaction; Ask keeps ownership of answer semantics and Tasks of plans/history. A separate public surface-registration API and independent preference files have not been added.

## Proposed live switch and rollback (not executed)

1. After explicit authorization, stop every affected Pi process. Back up `~/.pi/agent/settings.json`, both original `extensions/pi-{home,tasks}/` directories, and existing `pi-home.json`, `pi-footer.json`, and `pi-tasks.json` outside the agent's discovery paths. Record the original package/extension entries and checkout revision. Do not back up secrets or sessions into Git, and never delete session history or saved preference files.
2. Run `npm ci` in this checkout. Replace the two existing Frame/Ask package declarations in agent settings with **one** absolute path to this suite. Move or rename the original Home/Tasks extension directories outside `~/.pi/agent/extensions/` so auto-discovery cannot load them. Keep all preference files in place so the suite reads established values and migrates only when a user saves. Make these changes only after the remaining human acceptance checks and explicit authorization; never load both generations concurrently.
3. Start Pi cold. Inspect the loaded-resource list and `pi list`; verify one `/home`, `/footer`, `/tasks`, `tasks`, `ask_user_question` and `ask_questions`. Verify saved settings and Tasks history, native/Vim editor, question UI, fallback without Home, narrow/wide terminals and `/reload`. If a setting version is newer than this checkout, stop and assess it rather than overwriting it. Do not infer success solely from the package smoke test.
4. On any regression, stop Pi, restore the backed-up settings and extension directories, and cold-start; leave preference and session data untouched unless the user separately authorizes preference restoration. Check that the old standalone Frame/Ask declarations and Home/Tasks discovery paths are back, then reopen `/footer` and `/tasks`. A cold start avoids stale export maps across `/reload`. The isolated settings-removal/restore drill in [ACCEPTANCE.md](ACCEPTANCE.md) did not exercise live directory moves or prove this rollback on your machine.

This document does not authorize publishing, switching the live installation, or moving saved data. The suite is a **private local/packed package**, not a published release. Host Pi libraries remain peers; packed Frame is a declared bundled runtime dependency. Pin and test host compatibility before release.
